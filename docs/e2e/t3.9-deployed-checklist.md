### Found outside the checklist

`Darkness947/Full-Stack-To-Do-List` (tried by the human) failed with `ARCHIVE_LIMIT_EXCEEDED`.
- **Cause:** the repository commits `server/node_modules`. One entry, `server/node_modules/@mongodb-js/saslprep/dist/code-points-data-browser.js`, has a compression ratio of 217, which is above `MAX_COMPRESSION_RATIO` (100).
- **Why it aborts:** spec 7.5 step 2 applies the ratio check to *any* entry, including the ones the skip rules never inflate.
- **What it should give:** with the check limited to inflated entries, the repository gives 23 files, 24 dependencies and 2 unresolved (local run).

**Decision D-07 (user, 21 Nov 2026):** check the compression ratio only on the entries extraction keeps (source and root configuration files). Skipped entries are never inflated, so they cannot be a ZIP bomb. This is a recorded deviation from spec 7.5 step 2, fixed in this PR with unit tests.
- **NEON-TECH:** kept as is. Its 80.7 MB archive is over the 50 MB `MAX_ZIP_BYTES`, so it correctly fails.
